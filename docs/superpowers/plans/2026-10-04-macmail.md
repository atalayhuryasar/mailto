# MacMail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build MacMail, a lightweight, on-demand macOS `mailto:` router and default email application that routes clicked email links to native apps, webmail providers, custom URLs, or the clipboard based on configurable recipient and source-app rules.

**Architecture:** A modular Swift architecture composed of a headless `MacMailCore` framework (data models, RFC-compliant mailto parser, webmail URL builder, rule evaluation engine, and routing dispatcher) and a SwiftUI/AppKit host application (`MacMailApp`) with `LSUIElement = true` that acts on `mailto:` Apple Events, inspects the frontmost caller, evaluates routing rules, dispatches to the resolved target, and terminates cleanly when idle.

**Tech Stack:** Swift 6.4, macOS SDK (macOS 15+ compatible), SwiftUI, AppKit, LaunchServices (`lsregister`), CoreGraphics (`CGEventSource`).

## Global Constraints

- **Platform Target:** macOS 15.0+ (Sequoia / Tahoe compatible).
- **Execution Model:** On-demand execution (`LSUIElement = true`); 0% CPU and 0 MB RAM when idle; process terminates after routing unless the Settings window is open.
- **Sandboxing:** Sandbox disabled (`com.apple.security.app-sandbox = false`) for local installation and unrestricted `openURLs` / LaunchServices interoperability.
- **Identity & Branding:** Named `MacMail`, bundle ID `com.atalayhuryasar.macmail`, using the custom app icon in `_refs/icon.png`; no Mailway trademarks or verbatim copies.
- **Rule Semantics:** Recipient matching supports exact Email Address, exact Domain, and Domain & Subdomains. Multiple matchers are OR'd. Source apps condition is AND'd. No regex or subject/body rules. Priority order is determined strictly by list position (first match wins).
- **Modifier Override:** Holding the Fn (Globe) key unconditionally routes to the Alternative email app, bypassing all rules.

---

## Review Focus

1. **Percent-encoded query params in `mailto:`** (`mailto:?to=dev%2Bteam@work.com&subject=Fix%20%26%20Release`): parser must preserve `+` in email addresses, decode encoded query parameters without prematurely splitting at `%26` (`&`), and correctly generate target compose URLs.
2. **Excessive URL length safeguard for webmail** (body > 8,000 chars): `WebmailURLBuilder` must truncate or strip excessively large message bodies to prevent browser URL length limits (~32KB) from failing silently or crashing the browser.
3. **Missing or uninstalled target native app**: `TargetDispatcher` and `NativeAppLauncher` must verify bundle existence before invoking LaunchServices, falling back gracefully to the Primary target or alerting without process crash.
4. **Infinite routing loop prevention**: If a rule or setting selects MacMail itself as the target email app, the dispatcher must detect self-reference and reject invocation to prevent recursive launch cycles.
5. **Empty or recipient-less `mailto:` link** (`mailto:?subject=Feedback`): Parser and `RuleEngine` must handle empty recipient arrays safely, skipping recipient matchers without throwing, matching source-app rules if configured, or defaulting to the Primary target.
